D = Y Ψ, and the last stephandoff.md · gt-12-compression.tex:426–492

Now the fixed point. Define, for a machine M and a bound λ,

ΨM,λ(d)(n, x, y, a, b) = 1  if M halts within n steps,
                       = DCompress((Sλ, d), λ)(n, x, y, a, b)  otherwise.

Then DM,λ = Y ΨM,λ. If M never halts, the verifier at index n defers to the compressed verifier at a larger index, forever, and the game has a perfect entangled strategy at every level; if M halts at step T, the deferral bottoms out and the value drops. Deciding the value of the game therefore decides the halting problem — which is MIP* = RE.

Chapter 2's Y is exactly this combinator, and the implementation's Fix closes one self_code hole at constant charge rather than materialising the unfolding — which is what keeps |DM,λ| = O(|M| + log λ + 1) instead of unbounded. The TB7 run is specified to construct Fix(ΨM,λ), check that the embedded self_code hash equals the outer quote hash, simulate two steps of a non-halting M_loop, take the deferral branch, and execute the compressed decider without recursive host evaluation. It has not been run.

What this page does not claim. One description-level self-reference is not the infinite fixed-point value argument. The general value and λ-bounded conclusions of gt-12:502–519, 569–576 stay CITED, and so does every quantitative soundness and entanglement-dimension bound in the composition.

§15

How these claims were earnedverdicts/ · test/mutations/

A status only ever rises because an adversarial critic said so, and every green test has a mutant proving it can go red.

Each rung of the ladder is written by a proposer and then attacked by a critic that recomputes the numbers independently. The critic files a verdict with numbered objections; the proposer repairs; the next critic adjudicates the repairs and files fresh objections. A claim's status moves up only inside such a verdict — never because the author says so.

§16

The certificate treesrc/certificates.jl

Every bound in the prototype carries a derivation tree, and the leaves say honestly which of them were only cited.

Nothing returns a bare number. A construction returns a Checked{T,C} — the term together with a certificate whose nodes are graded. verify_certificate replays every CHECKED node against the constructor's own sub-terms, and refuses a certificate borrowed from another proof with :certificate_binding. These are the two real trees the suite printed.

Instrument · the trees, as printeddata/suite59q.log · click a node

Select a node to see its grade, what it asserts, and where its authority comes from.

CHECKED replayed from the constructor's own sub-terms CONSTRUCTED true by the datatype's invariants CITED an analytic theorem, not reproduced here ASSUMED a gap the code does not fill SOURCE_REPAIR the source as written does not typecheck; this is the repair
The point of the grades

A tree in which every leaf is CHECKED would be a lie. The value of the discipline is that CookLevinGeneral is visibly CITED, RawAnswerBlocks is visibly ASSUMED, and the five SOURCE_REPAIR nodes are visibly repairs — so a reader can locate exactly where this prototype stops being evidence and starts being transcription.
